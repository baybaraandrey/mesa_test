1. SOURCE / CONFIDENCE RULES
======================================================================

The project information comes from several different sources. Keep these distinctions
clear and do not promote an inference into a fact.

[A] DIRECTLY FROM MESA 7i97T MANUAL
- 7i97T has six +/-10 V analog servo outputs.
- 7i97T has six encoder interfaces.
- Each analog channel has an associated floating drive-enable output.
- TB3 contains ENA0..ENA5 and AOUT0..AOUT5.
- ENA outputs are floating optocoupler switches.
- ENA output rating: 50 mA max, 100 VDC max.
- ENA outputs are polarized; reverse polarity can damage them.
- For active-high drive enable:
      ENA+ -> positive control supply
      ENA- -> drive enable input
- For active-low drive enable:
      ENA+ -> drive enable input
      ENA- -> control power ground
- ENA0 through ENA3 are switched in common.
- ENA4 and ENA5 can be switched independently.
- Encoder interfaces can be differential or single-ended.
- Encoder interface provides short-circuit-protected +5 V power.
- Differential encoder interface has QA,/QA,QB,/QB,IDX,/IDX,+5V,GND.
- Analog interface recommendation:
      AOUTn -> drive AIN+
      adjacent Mesa analog GND -> drive AIN-
      use shielded twisted pair
      shield terminated at Mesa end
      separate drive-common / Mesa power-GND reference if required
- Analog outputs are +/-10 V, not 0..5 V.
- Analog output minimum load is 2 kOhm.
- Analog output max current is approximately 5 mA.
- 7i97T board itself requires regulated 5 V logic supply, 4.75..5.25 V.
- The isolated field inputs accept approximately +/-4 V to +/-36 V.
- Isolated inputs are intended for limit switches / control inputs.
- Six isolated outputs are floating MOSFET switch outputs, separate from the ENA outputs.

[D] PROJECT INFERENCE / DESIGN DECISION
The retrofit architecture is:
    LinuxCNC closes the OUTER position loop using the encoder.
    The old CMC drive remains the power amplifier / inner velocity servo.
    Motor tachometer stays connected to CMC.
    Motor encoder is moved to Mesa/LinuxCNC.
    Mesa sends +/-10 V analog command to CMC.
    LinuxCNC controls normal servo permission through Mesa ENA.
    Hardware E-stop / safety relay must ultimately be independent of LinuxCNC.

This architecture is the chosen retrofit design, not a statement that every old wire has
already been traced and proven.

3. ORIGINAL BURNY / CMC CONTROL ARCHITECTURE
======================================================================

The most important conceptual point is that the old machine already used a CLOSED LOOP
SERVO SYSTEM.

It was not a stepper machine.

Simplified original architecture:

    Burny Phantom ST motion controller
        |
        | analog servo command
        v
    CMC analog servo amplifier
        |
        | high-current DC armature power
        v
    PM DC servo motor
        |
        +---- tachometer feedback --------> CMC servo amplifier
        |
        +---- encoder feedback ------------> Burny motion controller

This is a nested-loop system.

INNER LOOP:
    CMC servo amplifier + motor tachometer
    The drive regulates motor velocity/current using local analog feedback.

OUTER LOOP:
    Burny controller + motor encoder
    The CNC knows actual axis position and adjusts the analog command.

The LinuxCNC retrofit intentionally keeps this same basic control philosophy:

    LinuxCNC
        |
        v
    Mesa 7i97T
        |
        | +/-10 V analog command
        v
    existing CMC servo amplifier
        |
        v
    existing PM DC servo motor

    encoder -------------------------------> Mesa 7i97T -> LinuxCNC
    tachometer -----------------------------> CMC drive only

Do NOT connect the motor tachometer to Mesa as the normal position feedback.
Do NOT connect motor armature directly to Mesa.
Mesa is a motion/control interface, not a motor power amplifier.

4.3 Encoder type / signals
--------------------------
The prior manual review established differential line-driver quadrature feedback:

    A
    /A
    B
    /B
    Index (I or Z)
    /Index (/I or /Z)
    +5 V
    0 V

The importance of differential signalling:
- A and /A are complements.
- B and /B are complements.
- Z and /Z are complements.
- A and B are quadrature channels.
- Z/index is a reference pulse, normally once per encoder revolution.
- Differential signalling is much more resistant to electrical noise than single-ended
  encoder signalling, which is important on a plasma machine.

Encoder connector mapping from our earlier Burny/manual investigation:

    Original encoder pin 9  A
    Original encoder pin 5  /A
    Original encoder pin 8  B
    Original encoder pin 3  /B
    Original encoder pin 6  Index / I / Z
    Original encoder pin 2  /Index / /I / /Z
    Original encoder pin 7  +5 V
    Original encoder pin 1  0 V

Again: pin 4 is not assigned in our current verified notes.

4.4 Encoder feedback and drive tach feedback are separate
---------------------------------------------------------
This distinction is critical:

    ENCODER -> CNC controller / now Mesa + LinuxCNC
    TACH    -> CMC servo drive

The encoder is the machine position feedback.
The tachometer is the drive's local velocity feedback.

4.5 Motor tuning exists as a controller-level activity
-------------------------------------------------------
The Burny manual includes motor setup/tuning procedures, reinforcing that the old CNC
closed a motion loop around the analog servo system. LinuxCNC will now perform that
outer control function.

4.6 Process control is integrated but is a later phase
------------------------------------------------------
The Burny system also handled plasma / oxy-fuel process functions and lifter controls.
For the first retrofit phase we are NOT reproducing all of that at once.

Current strategy:
- first establish reliable motion/control hardware
- keep plasma disabled
- later integrate torch start, Arc OK and THC
- initially retain Hypertherm Sensor PHC if functional

6. WHAT EACH IMPORTANT CMC J1 SIGNAL MEANS FOR THE RETROFIT
======================================================================

J1-4 COMMAND+ and J1-5 COMMAND-
--------------------------------
These are the analog motion command inputs.

Mesa will generate approximately -10 V .. 0 V .. +10 V.

Expected conceptual behavior:
    positive command -> motion one direction
    zero command     -> zero velocity demand
    negative command -> opposite direction

The direction sign may need correction in LinuxCNC configuration after safe testing.

J1-1 +10 V OUT and J1-3 -10 V OUT
----------------------------------
These are drive-generated reference outputs, labelled 5 mA.

They are NOT the source for the Mesa analog motion command.
Mesa generates its own +/-10 V command.

They may later be useful as control references for J1-11 only if the drive input behavior
and required current are verified. Do not assume this yet.

J1-6 TACH IN and J1-7 COMMON
----------------------------
Leave the motor tachometer on the CMC drive.

The tach is part of the drive's inner velocity loop.

J1-8 CURRENT MONITOR OUT
------------------------
Diagnostic output. Not needed for basic Mesa motion control.

J1-9 CURRENT REF
----------------
Do not repurpose without documentation.

J1-11 INHIBIT/RESET
-------------------
This is the important unresolved drive-permission input.

Conceptually it determines whether the drive is permitted to produce motor torque and/or
is used to reset a latched drive fault.

We do NOT yet know its electrical truth table.

Possible examples ONLY:
    +10 V -> enabled, 0 V/open -> inhibited
OR
    0 V/common -> enabled, open/high -> inhibited

It may also use a transition/pulse for RESET.

DO NOT encode either polarity as a fact until measured on the original wiring.

Required measurement:
    black meter/scope reference -> J1-2 COMMON
    measure J1-11 under:
        drive disabled
        normal ready/enabled state
        E-stop
        reset-button action

Use oscilloscope if reset may be a short pulse.

J1-12 / J1-13 LIMIT SWITCH +/-
--------------------------------
These appear to be drive-side limit / inhibit functions.

Do not connect them blindly to Mesa.
Our first limit-switch implementation uses Mesa isolated inputs for LinuxCNC observation.
A later safety design may also use the drive-side limit function or safety relay.

J1-14 FAULT OUTPUT
------------------
Eventually this should report drive health to LinuxCNC and possibly the hardware safety
system.

But its electrical type is not yet confirmed:
- open collector?
- relay/contact?
- active-high voltage?
- active-low?
- referenced to drive common?

Measure before connecting to Mesa.

7.3 Important ENA behavior
--------------------------
Mesa documentation:
- ENA outputs are floating optocoupler switches.
- maximum 50 mA
- maximum 100 VDC
- polarized
- active-high wiring:
      ENA+ to positive control supply
      ENA- to drive enable input
- active-low wiring:
      ENA+ to drive enable input
      ENA- to control-power ground
- ENA0..ENA3 switch in common
- ENA4 and ENA5 can be switched independently

This means the ENA pair is conceptually an electronic switch, not a +5 V logic output.

If the CMC J1-11 ultimately requires positive voltage:
    positive control voltage
        -> ENA0+
        -> [Mesa electronic switch]
        -> ENA0-
        -> CMC J1-11

If CMC J1-11 ultimately needs to be sunk to common:
    CMC J1-11
        -> ENA0+
        -> [Mesa electronic switch]
        -> ENA0-
        -> CMC COMMON

We are NOT choosing one of those physical CMC wiring cases yet.
Current task only verifies that LinuxCNC can command the Mesa ENA electronic switch.

8. LIMIT / HOME SWITCH APPROACH
======================================================================

Preferred field wiring is 24 V and normally-closed contacts where practical.

Example:
    +24 V -> NC limit switch -> Mesa INx
    0 V   -> corresponding Mesa input COMMON

Reason for NC:
- normal state proves wiring continuity
- broken wire can become a fault condition
- triggered switch becomes a fault condition

Current LinuxCNC work has already involved mapping a physical Mesa input to joint limit /
home signals.

    joint.0.home-sw-in

13. PHYSICAL BENCH TEST OF ENA0
======================================================================

Current test is intentionally performed BEFORE connecting CMC J1-11.

Mesa connector:
    TB3-1 = ENA0-
    TB3-2 = ENA0+

Goal:
verify that changing LinuxCNC Machine ON/OFF changes the physical ENA0 switch state.

Because this is a semiconductor/opto switch, a simple DMM continuity test may or may not
be the best indication depending on meter behavior. A safe low-voltage current-limited
test circuit is acceptable.

Do NOT apply voltage above Mesa ratings.
Observe ENA polarity.
Do NOT connect the CMC drive yet.

A useful validation sequence:
1. Start LinuxCNC.
2. Leave E-stop active.
3. Confirm HostMot2 enable HAL pin false.
4. Reset E-stop but leave Machine OFF.
5. Confirm false.
6. Machine ON.
7. Confirm joint amp-enable true and HostMot2 enable true.
8. Observe ENA0 external test circuit switch/conduct.
9. Machine OFF.
10. Confirm switch stops conducting.
11. Re-enable, then press E-stop.
12. Confirm it immediately returns to disabled state.

16. ENCODER TEST / PRODUCTION ENCODER NOTES
======================================================================

For the production encoders, all eight encoder conductors are expected to be used:

    A
    /A
    B
    /B
    Z/index
    /Z/index
    +5 V
    GND

Mesa supplies +5 V and GND at each encoder terminal group.

A logic analyzer can be used to identify unknown signal wires:
- logic-analyzer GND -> encoder 0 V
- observe six signal wires simultaneously
- complementary pairs identify A//A, B//B, Z//Z
- index pair occurs once per revolution
- A/B are quadrature

A logic analyzer can identify complementary pairs but may not by itself determine the
desired machine convention for "A versus /A" or which pair should be called A versus B.
Direction is ultimately verified using Mesa/LinuxCNC counts.

Do not treat cable shield as encoder 0 V.

The Mesa AOUT output is +/-10 V analog servo command.

The "5 mA" figure is current capability, not a 5 V output range.

Do not confuse:
    Mesa board +5 V logic supply
with:
    Mesa +/-10 V analog servo output
or:
    CMC J1-1 +10 V / J1-3 -10 V reference outputs.

The analog command should ultimately be tested with drive disabled first:
- command small values
- measure J1-4 relative to J1-5
- verify zero command
- verify positive and negative command
- only then consider enabling a drive.

======================================================================
18. SERVO SAFETY / RUNAWAY RISK
======================================================================

Wrong command polarity or wrong encoder polarity can cause immediate positive feedback
and servo runaway.

Therefore final motion commissioning sequence:
1. Plasma disabled.
2. One axis at a time.
3. Other drives physically prevented from unexpected activation.
4. Encoder verified before closing position loop.
5. Very low speed.
6. Very low acceleration.
7. Conservative following-error limits.
8. Low/known PID gains.
9. E-stop immediately accessible.
10. Hardware safety path independent of LinuxCNC.

For a correctly signed closed loop:
    positive commanded motion must produce feedback of the corresponding sign expected
    by LinuxCNC.

If encoder direction is wrong, correct configuration/wiring deliberately.
Do not randomly reverse both command and feedback signs.

19. GANTRY / XX AXIS
======================================================================

The original machine has labels X, Y, XX and Aux.

XX is believed to be the second motor on a dual-drive gantry, but this must be physically
confirmed.

If X/XX are a gantry pair:

- each side should have its own home/reference switch if possible.
- homing should square the gantry.
- incorrect independent movement can rack/twist the gantry.

Do not expand the current ENA test into gantry configuration work.

21. SAFETY ARCHITECTURE — FINAL TARGET
======================================================================

LinuxCNC normal machine-enable is NOT the only safety mechanism.

Target:
    E-stop / safety devices
        -> hardware safety relay
            -> remove servo permission / contactor
            -> independent of PC/LinuxCNC
        -> LinuxCNC receives status

LinuxCNC:
    handles normal machine enable/disable
    sees faults
    sees limit/home status
    commands normal servo enable

Hardware:
    must be capable of removing drive torque independently of software

The present ENA0 HAL test is functional testing, not final safety validation.
